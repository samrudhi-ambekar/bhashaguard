# Privacy and Safety Notes

BhashaGuard is a privacy-conscious prototype, not a claim that page data never leaves the
machine. A scan sends the current viewport screenshot and visible text candidates to a
local backend, and that backend sends them to an external Gemini API for analysis.

## What is collected

When the user starts a scan, BhashaGuard collects:

- a screenshot of the current browser viewport;
- visible text candidates from that viewport, including candidate IDs, text, and HTML tag
  names;
- viewport dimensions;
- a random session identifier generated by the content script.

BhashaGuard does not collect the current page URL in the analysis payload. The popup uses
the tab URL only to reject unsupported pages and to show a hostname.

## Where data goes

1. The extension sends the screenshot and candidates to the local Express service at
   `http://127.0.0.1:8787`.
2. The local service uploads the screenshot to the Gemini Files API and sends the
   screenshot plus candidate text to the configured Gemma model through the official
   `@google/genai` SDK.
3. The local service attempts to delete the uploaded screenshot in a `finally` block.
   Uploaded files also expire according to the external provider's policy.
4. BhashaGuard does not intentionally persist scan data or maintain a review history.

Google's handling of API data is governed by the applicable Google API terms. Review those
terms before sending screenshots or text from sensitive pages.

## API key handling

- The Gemini API key belongs only in `server/.env`.
- `server/.env` is ignored by Git; use `server/.env.example` as the template.
- The key is never included in extension code, extension requests, analysis responses, or
  documentation.
- The local `/health` endpoint reports only whether a key is configured and the model name.
- Do not place a real key in screenshots, issues, logs, test fixtures, or commits.

## Permissions

The extension manifest requests:

- `activeTab`, to act on the tab the user is currently viewing;
- `scripting`, to inject the visible-text scanner and correction core;
- host access to `http://127.0.0.1:8787/*`, the local analysis service.

Scans are user-initiated. BhashaGuard does not continuously read pages or run in the
background.

## Safety controls

- The model response is treated as untrusted data.
- The backend rejects unknown candidate IDs, mismatched original text, duplicate findings,
  unsupported categories or severities, HTML, control characters, and oversized fields.
- The popup validates findings again before displaying them.
- Model-generated HTML or JavaScript is never executed.
- Apply requires an actionable candidate, a validated plain-text replacement, and an
  unchanged original text node.
- Undo restores text only when the node still contains the exact replacement BhashaGuard
  applied.
- Nested, ambiguous, stale, or unsafe targets are rejected.
- Corrections modify only the current page's DOM. They do not modify the website server.
- Reloading the page removes temporary corrections.

## User responsibilities

- Only scan pages you are authorized to send to the configured model provider.
- Avoid scanning pages containing personal, confidential, financial, health, or
  credential data unless you have the right to do so.
- Treat screenshots as potentially sensitive. Do not publish captures containing private
  tabs, account details, keys, or personal information.
- Review every suggested translation before applying it. Model output can be wrong.

## Limitations

- Scans cover only the current viewport, not the whole page or website.
- At most 40 unique visible candidates are analyzed per scan; a partial scan is labelled.
- There is no batch Apply, batch Undo, persistent review history, or site crawl.
- The tool does not assess keyboard access, screen-reader behavior, color contrast, or
  legal compliance.
- The local backend binds to loopback, but it still calls an external API.
- Automated browser tests stub Chrome APIs and do not replace a manual installed-extension
  check.
- BhashaGuard has no affiliation with, endorsement from, or validation by DVET or the
  Government of Maharashtra.

## Reporting a privacy or security issue

Do not open a public issue containing a real API key or private page data. Revoke any
exposed key, remove the sensitive material, and report the problem through the repository's
private contact channel if one is available.
